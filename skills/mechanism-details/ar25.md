# ar25 — reflection-rotation-fit

## Summary
The player clicks to select a movable shape sprite, then nudges it 1 cell at a
time across the grid until every "8"-coloured pixel on its boundary lines up
with another shape's matching boundary "8". The board contains horizontal
("zxikvwjsyl") and vertical ("ezdsyuixsn") reflector lines that copy-mirror
sprite pixels through them, so a single placement counts simultaneously at its
real position and at its reflected position. Some shapes are auto-rotated when
they cross particular reflector lines, and a step-counter HUD drains each
action — the puzzle is essentially "tile the plane modulo the reflector
group". The win condition is mutual: every collidable boundary on every shape
must be matched.

## Action mapping

| Action | Semantic (game-specific) | Gate / when valid |
|---|---|---|
| ACTION1 | Move selected shape up 1 cell | a shape is selected |
| ACTION2 | Move selected shape down 1 cell | a shape is selected |
| ACTION3 | Move selected shape left 1 cell | a shape is selected |
| ACTION4 | Move selected shape right 1 cell | a shape is selected |
| ACTION5 | Rotate selected shape 90° clockwise | a shape is selected |
| ACTION6 | Click a shape on the board to select / deselect it | always |
| ACTION7 | Undo last move (state stack `usukvgwle`) | undo stack non-empty |

## Per-level mechanic progression

| Level | Mechanic introduced (or composed) | Specific challenge / constraint |
|---|---|---|
| 1 | Free move + click-select; a single horizontal reflector | learn that the reflector duplicates the sprite — fit two halves with one move |
| 2 | Two reflectors (horizontal + vertical) acting as a 4-quadrant mirror | both axes' "8" connectors must align simultaneously |
| 3 | Multi-shape board: several pieces with disjoint "8" boundaries | identify which piece pairs with which without disturbing solved pairs |
| 4 | `reflect_horizontal_only` / `fmxjsieygg` (vertical-only) tags | each piece participates in only ONE axis; routing must respect tag |
| 5 | Rotation-required: piece's "8" pattern only matches after 90° rotation | combine ACTION5 with ACTION1-4; step budget tightens |
| 6 | Asymmetric pieces of different shapes (`xnpsicjqxc`/`dmfgetmeus` tagged distance hints) | distance hints `ueryufapb` cached at level start |
| 7 | Larger grid, more pieces, both reflectors, mixed reflect-axis tags | full composition of all earlier rules |
| 8 | Border / "pwbzvhvyzx" non-movable obstacles + larger search depth (BFS depth 12 for reflection traversal) | path-of-pixels through reflectors must avoid borders |

## Win condition
After every move/rotate/click, the renderer rebuilds an integer grid covering
canvas + reflected images, and checks that no live "8" pixel is unmatched
(`mbpwomuihy` BFS up to depth 12). If complete, `self.next_level()` fires.
After the last level, base class auto-calls `self.win()`.

## Lose condition
Step counter HUD `zdrbnrjbr` drains by 1 per non-RESET action; when it hits
zero `self.lose()`. There is no instant-fail collision — wasting moves is the
only failure.

## Internal state
- selected sprite (obfuscated `llludejph`)
- movable shapes list `migkdsjrwk` (tag `gljpmsnsnx`)
- reflector-axis sprites `khupblbrxc` split into `hnepuikbu` (horiz) /
  `hitrtbsoq` (vert)
- distance-hint dict `ueryufapb` (sprite → axis distance, used for hint UI)
- undo state stack `usukvgwle` (typed `gluxplkybg = TypedDict`)
- step counter `zdrbnrjbr` (RenderableUserDisplay)
- tutorial-arrow sprite (`cxnxzbeld`) shown level 1 only

## Notable code patterns
- BFS over reflector axes: each cell can spawn up to 2 mirrored cells, capped
  at depth 12; this is reusable for any "modular wallpaper" mechanic.
- Tag-gated reflection: `reflect_horizontal_only` / `fmxjsieygg` tag on a
  sprite vetoes the orthogonal axis. Clean way to give per-shape rules.
- Pre-cached rotated pixel grid via `np.rot90(sprite.pixels)` with re-anchored
  position keeping the visual centre fixed.
- Undo: typed dict snapshots `(sprite_id, x, y)` per movable, restored on
  ACTION7. Cheap O(N) snapshot.
- HUD shape pair: `cxnxzbeld` (instructions / arrow) + `zdrbnrjbr` (steps).
