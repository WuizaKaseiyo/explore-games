# tn36 — program-shape-buttons

## Summary
The board has a "working shape" sprite plus a row of instruction buttons
(move/rotate/resize). Clicking an instruction button (ACTION6) appends an
opcode to a tape that immediately executes on the working shape. The working
shape scrolls offscreen via a constantly-advancing scroll position, and the
goal is to make the working shape match a target shape before the target
scrolls off-screen. The world model `tsflfunycx` (`tdoawrudpq`) holds the
shape state and per-tick simulation; `qzfhantdjf` (`yrddcregck`) is a window-
scroll/timer wrapper.

## Action mapping

| Action | Semantic (game-specific) | Gate / when valid |
|---|---|---|
| ACTION6 | Click an instruction button (move/rotate/resize/etc.) — appends to tape and executes | always, while not in animation |

(`available_actions=[6]` — pure click.)

## Per-level mechanic progression

| Level | Mechanic introduced (or composed) | Specific challenge / constraint |
|---|---|---|
| 1 | Single move op; small scroll; large target tolerance | tutorial: click move, see effect |
| 2 | Add rotate buttons (90° increments) | combine move + rotate |
| 3 | Add resize buttons (extend/shrink) | shape now varies in pixels too |
| 4 | Tighter scroll budget; instruction effects branch on shape state | program planning |
| 5 | Multiple working shapes selectable | switch active before each instruction |
| 6 | Target shape itself transforms over time (animated target) | racing reactive target |
| 7 | Composite: full instruction set, scrolling target, multiple shapes | full stack |

## Win condition
`woaawujmbs()` returns `tsflfunycx.yxabhsirzl` — world model's "shape matches
target" flag. → `self.next_level()`.

## Lose condition
`jbrycdcplp()` returns `not qzfhantdjf.fisapprjnh` — scroll wrapper's "still
in window" flag goes False (target scrolled offscreen). → `self.lose()`.

## Internal state
- world model `tsflfunycx` (`tdoawrudpq`) — shape state + tape execution
- scroll/timer wrapper `qzfhantdjf` (`yrddcregck`) — tracks how much of the
  visible window is still on-screen
- pending-flags `rarvldaizc` (win this step) and `eaecsuhysh` (lose this step)
- `tsflfunycx.nwjrtjcxpo` — animation in-progress flag

## Notable code patterns
- World-model owns simulation: `tsflfunycx.csaytdwcpe(x, y)` interprets the
  click as an instruction (op selected by which button). `kywgygufid()` runs
  one tick. Game class is just dispatch.
- Two-flag commit pattern (used in g50t, tn36): `rarvldaizc=True` marks win
  pending; next step calls `next_level()`. Lets animation finish first.
- Scroll-offscreen as lose: `qzfhantdjf.fisapprjnh` — the scroll counter
  acts as the budget. Visually the target moves left at constant rate.
- Camera-coords-to-grid via `vovghntqtf()` wraps `display_to_grid`.
