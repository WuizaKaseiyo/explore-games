# m0r0 — mirrored-quad-control

## Summary
Four avatars are placed on the board: top-left, top-right, bottom-left,
bottom-right. A single direction press moves all four simultaneously, but
each one's axes are sign-flipped relative to the canonical (top-left)
direction (TR is x-mirrored, BL is y-mirrored, BR is xy-mirrored). The goal
is to bring pairs of avatars onto the same cell (they merge and become
intangible). Once all four merge into pairs, level wins. Clicking a "lever"
sprite (`cvcer`) toggles a mode where you only move one selected avatar
instead of all four.

## Action mapping

| Action | Semantic (game-specific) | Gate / when valid |
|---|---|---|
| ACTION1 | Move all four avatars (or selected one) up; mirrored per-quadrant | not in merge animation |
| ACTION2 | Move all four / selected down; mirrored per-quadrant | as above |
| ACTION3 | Move all four / selected left; mirrored per-quadrant | as above |
| ACTION4 | Move all four / selected right; mirrored per-quadrant | as above |
| ACTION6 | Click a `cvcer` lever to toggle single-control mode | always |

## Per-level mechanic progression

| Level | Mechanic introduced (or composed) | Specific challenge / constraint |
|---|---|---|
| 1 | All four avatars in symmetric layout, no walls | tutorial: one direction press merges all four |
| 2 | Asymmetric obstacle (`jggua` tag) — one avatar hits a wall, others continue | learn that some moves only affect a subset |
| 3 | "Mirror walls" `nhiae` introduced — block individual axes | avatar-specific blockage forces decoupling |
| 4 | Lever (`cvcer`) introduced — click to enter single-avatar mode | switch between collective and individual control |
| 5 | Multiple rooms; three avatars must merge in one room while fourth comes from another | mode-switching essential |
| 6 | Walls of all three types + multiple levers; complex pairing | full stack |

## Win condition
After every move, `dawfcldxmo` filters non-removed avatars; pairs are merged
when two land on the same cell (or two adjacent ones swap on each other's
prior position). Avatars marked INTANGIBLE. When all four are intangible,
`self.next_level()`.

## Lose condition
Step counter `tmbjb` (`lradlpwbhu`, default 150) drains. When
`_action_count > 150`, `self.lose()`.

## Internal state
- selected avatar (obfuscated `cfwgj`, set by clicking a `cvcer` lever)
- single-control mode flag `vmcbq` (False = move all four together)
- merged set `fqunj` (names of avatars already merged)
- previous positions `bwyvb` (used to detect "swap")
- step counter HUD `tmbjb`, action UI `erwkb` (`kyrgqgqaes`)
- merge animation list `yvmbd` and tick `zgdmc` (-1 = idle, 0..6 = animation)
- `myxvz` — list of (sprite, x, y) snapshots for restoring lever positions
  after merge animation

## Notable code patterns
- Per-quadrant axis flipping: avatar names encode their quadrant (`ubwff`/
  `kncqr` for vertical, `idtiq`/`crkfz` for horizontal). For each direction,
  flip dx/dy by name match. Reusable as "control multiple things with
  reflected axes".
- Merge-on-same-cell: after every move, group avatars by `(x,y)`; pairs of
  size 2 merge by setting `InteractionMode.INTANGIBLE`.
- Swap detection: if A ends at B's prior position and B ends at A's prior
  position (Manhattan-1 separated), force them both to the midpoint cell —
  prevents "passes through each other" exploit.
- Wall-tag groups: `jggua` (hard walls), `nhiae` (mirror walls), `dfnuk-*`
  (per-direction walls). Each group has different blocking semantics.
