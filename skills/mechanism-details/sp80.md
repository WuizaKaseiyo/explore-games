# sp80 — liquid-flow-routing

## Summary
The player picks a placeable pipe-piece (selecting via ACTION6 click on
`hfjpeygkxy`/`ksmzdcblcz` tiles) and moves it on the board with WASD;
ACTION5 commits the level configuration and triggers a flow simulation:
liquid drops from each spawn point (`syaipsfndp`) into adjacent cells,
following bend rules around pipe-pieces, walls (`xsrqllccpx`), and sinks
(`uzunfxpwmd`). Steps tick down per turn, and after 4 unsuccessful spills
the level is lost. A tilt mechanic rotates the entire input axes (set via
`rotation` level data: 0/90/180/270). The player must commit a layout in
which liquid reaches all sinks.

## Action mapping

| Action | Semantic (game-specific) | Gate / when valid |
|---|---|---|
| ACTION1 | Move selected piece up (rotated by `sywpxxgfq` axis) | a piece is selected; not mid-spill |
| ACTION2 | Move selected piece down (rotated) | as above |
| ACTION3 | Move selected piece left (rotated) | as above |
| ACTION4 | Move selected piece right (rotated) | as above |
| ACTION5 | Commit layout; spawn liquid; run flow simulation | not mid-spill; ≤ 4 spills used |
| ACTION6 | Click a piece to select it (only `hfjpeygkxy` / `ksmzdcblcz` tagged) | always (deselects current first) |

## Per-level mechanic progression

| Level | Mechanic introduced (or composed) | Specific challenge / constraint |
|---|---|---|
| 1 | Single sink, single pipe-piece; spawn → spill | tutorial: place piece between spawn and sink, ACTION5 |
| 2 | Walls block direct path; pipe-piece must redirect | introduces bend rule |
| 3 | Multiple sinks (`uzunfxpwmd`) | every sink must fill |
| 4 | Multiple spawn points (`syaipsfndp`) | each spawns own liquid current |
| 5 | Tilt: input axes rotated 90° (`rotation = 90` in level data) | left = down, etc. |
| 6 | Composite: tilt + walls + multiple sinks + 4-spill cap | full stack |

## Win condition
After spill animation finishes, `self.srwrqoodsc` (set of touched walls) plus
`self.szbmtoxgbd` (touched sinks) must cover every `mldlhgjtqi` (wall tag) and
every `uzunfxpwmd` (sink). When `inszeuniyy` is True, fires `self.next_level()`
after the post-spill flash sequence.

## Lose condition
- step counter `tunzhnhfa` (default 50, from `steps` level data) reaches 0
- 4 unsuccessful spills (`zzocrmvox >= 4`) on ACTION5 → `self.lose()`

## Notable code patterns
- Liquid as cellular automaton: `tadqvfdobr` seeds drops at each
  `syaipsfndp` (spawn) cell, then per-tick checks 8-neighbour interactions
  with walls/sinks/pipes/pillars and spawns the next-tick fluid sprites
  accordingly. Reusable as "1-cell-per-tick flood".
- Tilt via permutation tables: `wdxitozphu[k]` maps incoming action ids to
  rotated equivalents; `qxlcnqsvsf[k]` is the inverse for `_get_valid_actions`.
  Reusable for any rotated-axis input.
- Click coords are also rotated via `udeubouzyp` before being mapped to the
  grid.
- Multi-tick flash animation when level fails: cycle a colour pair through
  6 ticks (`jmbhqnxkkc<6`) on touched cells. Cheap visual.
- 4 sprites pre-flagged as fluid (`syaipsfndp` tag) act as spawn points; no
  pixels are placed until ACTION5.
