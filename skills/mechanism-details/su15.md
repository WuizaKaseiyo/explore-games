# su15 — radial-blast-capture

## Summary
The player has a single click action (ACTION6 on a 16×14 cell grid) and an
undo (ACTION7). Each click detonates a radial "vacuum" blast at the click
point: every fruit (`peiiyyzum`) within radius is sucked toward the blast
centre and consumed. Enemies are also pulled, but if any enemy is engulfed,
the blast fails and counts as a strike (`bjetwxoaq` cap). The level wins when
all fruits and all "key" sprites (`koprtgesg`) are collected. A hint sprite
is shown on level 1; visual feedback comes from animated phases (`vacuum`,
`flash`, `win`).

## Action mapping

| Action | Semantic (game-specific) | Gate / when valid |
|---|---|---|
| ACTION6 | Detonate a radial blast at clicked cell | always; cell quantised to 16×14 grid (x in [0..63] step 4, y in [10..58] step 4) |
| ACTION7 | Undo to previous snapshot (state stack `dqxbwefew`) | snapshot stack non-empty |

(`available_actions=[6, 7]`. Pre-enumerated valid actions: 16×14=224 ACTION6
candidates plus undo.)

## Per-level mechanic progression

| Level | Mechanic introduced (or composed) | Specific challenge / constraint |
|---|---|---|
| 1 | Few fruits, no enemies, hint sprite shown | tutorial: click anywhere to suck nearby fruits |
| 2 | Enemy (`hsvtuyfsue`-like tag) — pull strength engulfs them on too-close click | learn safe radius |
| 3 | Multiple fruit groups; one blast can't get all | sequence multiple blasts |
| 4 | Walls block fruit movement during pull | line-of-sight matters |
| 5 | Strikes counter (`bjetwxoaq`) ramps; 3 wasted blasts → fail | budget pressure |
| 6 | Multiple enemies in formation; precise spacing required | high-precision blast |
| 7 | Key sprites that act like fruits but with different visual | win-set is union |
| 8 | Composite: enemies + walls + keys + step budget | full stack |
| 9 | Final composite | nothing new |

## Win condition
`kouxmshyjy()` returns True when all fruits (tag `bjquaudhya`) are removed
AND all keys (tag `koprtgesg`) collected. Then `inhlatxex='win'`,
`win_frame` ramps to 10, → `self.next_level()`.

## Lose condition
- `bjetwxoaq` strikes (engulfed enemies) hit `aevhcnismc` → `self.lose()`
- step counter `step_counter_ui` (`musowtfgnt`, default 128) hits zero
- no fruits remaining but keys uncollected (state inconsistent)

## Internal state
- player blast list (none — clicks are stateless detonations)
- fruit list `hmeulfxgy` (tag `bjquaudhya`)
- enemies `peiiyyzum` (3 sub-types unioned, each tagged)
- key/coin list `koprtgesg`, hint sprite `liesgkdzq`
- pull-physics dicts: `itlxknnsz`, `rzfgsshuk`, `npdhdupen`, `nbnfqojis`,
  `zwgbpzcgq`, `mdomdbjdo`, `dwehbjuln` — each maps a sprite to its current
  trajectory or count of in-pull frames
- animation phase string `inhlatxex` — "none"/"vacuum"/"flash"/"win"
- snapshot stack `dqxbwefew` (list of (name, x, y, layer) tuples for undo)
- HUD UI: `gcpqtwbmkp` background sprite + step counter

## Notable code patterns
- Radial pull as physics dict: each affected sprite gets a
  `(velocity_x, velocity_y)` entry that `lyaaynsyhw` ticks per step. Once
  trajectory ends, sprite removed if it's a fruit.
- Pre-enumerated 224 ACTION6 candidates: cell-quantised input space lets the
  agent treat the world as a tabular policy.
- Snapshot for undo: `(name, x, y, layer)` tuple per sprite — including
  layer means re-spawning preserves z-order.
- Animation phase enum (`vacuum`/`flash`/`win`) with per-phase frame counts —
  clean state machine.
- Radial mask via numpy meshgrid `sqehcqhws, qwmmebmhb`: pre-computed once
  in `on_set_level`; per-blast just thresholds distance.
