# wa30 — carry-pickup-drop

## Summary
The player controls a single carrier (`wbmdvjhthc`) on a grid of cells
spaced `celomdfhbh` apart. ACTION1-4 step the carrier in cardinal directions;
ACTION5 picks up an adjacent item or drops a held item on an adjacent target.
The level wins when every "passenger" sprite (`geezpjgiyd`) has been
delivered to a "destination" sprite (`fsjjayjoeg`) — i.e. every passenger is
on a destination cell, with no remaining tethered partner. While idle,
passengers and "secondary" sprites (`ysysltqlke`) auto-pathfind toward their
own targets via BFS (`czrprbohhe`, `cyjrduhzmz`, `egqayvffim`,
`zauouvdhta`).

## Action mapping

| Action | Semantic (game-specific) | Gate / when valid |
|---|---|---|
| ACTION1 | Step carrier 1 cell up (rotate to face up) | always; blocked if next cell is in `pkbufziase` (occupied) or `qthdiggudy` (forbidden) |
| ACTION2 | Step carrier down | as above |
| ACTION3 | Step carrier left | as above |
| ACTION4 | Step carrier right | as above |
| ACTION5 | Pick up / drop / release nearby item | always; behaviour depends on what's adjacent |

(`available_actions=[1, 2, 3, 4, 5]` — no clicks.)

## Per-level mechanic progression

| Level | Mechanic introduced (or composed) | Specific challenge / constraint |
|---|---|---|
| 1 | One passenger, one destination | tutorial: walk to passenger, ACTION5, walk to destination, ACTION5 |
| 2 | Forbidden cells (`bnzklblgdk`) constrain navigation | route around forbidden cells |
| 3 | Two passengers; pick up one at a time | interleave deliveries |
| 4 | "Forbidden-for-passenger" cells (`zqxwgacnue`) — passengers refuse to step there | passenger-aware routing |
| 5 | Secondary tethered sprite (`ysysltqlke`) — auto-walks; carrier can release it | management of an extra mobile sprite |
| 6 | Multi-step delivery: pick up A, take to B's location, swap | combinatorial pickups |
| 7 | Tight step budget (data `StepCounter`) | optimise paths |
| 8 | Composite: many passengers, forbidden zones, secondaries | full stack |
| 9 | Composite final: tightest budget + most agents | nothing new, full stack |

## Win condition
`ymzfopzgbq()`: every `geezpjgiyd` passenger is at a destination cell
(`shbxbhnhjc((x,y))`) AND has no carrier tethered. → `self.next_level()`.

## Lose condition
Step counter `kuncbnslnm` (`etuniyewsy`) drains; reaches 0 → `self.lose()`.

## Internal state
- step counter `kuncbnslnm` (`etuniyewsy`)
- pickup map `nsevyuople` (carrier → tethered sprite) and inverse `zmqreragji`
- occupied cells set `pkbufziase`
- destination cells `wyzquhjerd`, "forbidden for passenger" cells
  `lqctaojiby`, "absolute forbidden" cells `qthdiggudy`
- BFS-targets for live passengers: `lkvghqfwan` (cells adjacent to free
  passengers), `uuorgjazmj` (cells adjacent to free secondaries)
- Cell stride `celomdfhbh` (e.g. 4 for 16×16 sprite cells on 64×64 canvas)

## Notable code patterns
- BFS pathfinding (`czrprbohhe`/`cyjrduhzmz`/`egqayvffim`/`zauouvdhta`):
  walks from a sprite toward its destination cell respecting
  free/forbidden/blocked sets. Auto-pilot for non-player sprites.
- Tethered carry: when carrier picks up a passenger, store the offset; on
  carrier move, validate that both passenger and carrier slots are free
  (`fuykgiiwit`). Reusable as "rigid pickup".
- Per-action visual update: `zzppkjnqgk` repaints each passenger sprite by
  status (carried, on-destination, neither) using `vlzkmytlgh`/`hgqlwjikqr`/
  `qrmfayeqpo`/`wvrpthjfsv` colours.
- Cell-snapping coordinates: every position is multiples of `celomdfhbh`,
  so collision is set membership on a tuple — `(x, y) in pkbufziase`.
- Self-pathfinding NPCs: each tick, secondaries call BFS toward their
  free-target set and step one cell along the path.
