# g50t — ghost-replay-multitarget

## Summary
The player moves a single avatar with arrow keys and presses ACTION5 to
"commit" a path. After a commit, the avatar respawns at the start while the
prior path replays as a ghost. A timer-style sprite (`twyixucrqi`) scrolls
left across the screen one cell every two action-counts — once it falls fully
off-screen the level ends. The puzzle is to chain multiple ghost paths so
that the union of all paths covers every required target cell before the
timer scrolls off.

## Action mapping

| Action | Semantic (game-specific) | Gate / when valid |
|---|---|---|
| ACTION1 | Move avatar up 1 cell | not in animation phase |
| ACTION2 | Move avatar down 1 cell | not in animation phase |
| ACTION3 | Move avatar left 1 cell | not in animation phase |
| ACTION4 | Move avatar right 1 cell | not in animation phase |
| ACTION5 | Commit current path as a ghost; respawn at start | always |

(No ACTION6 — pure WASD + commit.)

## Per-level mechanic progression

| Level | Mechanic introduced (or composed) | Specific challenge / constraint |
|---|---|---|
| 1 | Single target; one path required; long timer | tutorial: walk to target → press ACTION5 |
| 2 | Two targets simultaneously reachable in one path | learn to plan a path that hits both |
| 3 | Two targets unreachable in one path → must use ghost replay | introduce ACTION5 as essential |
| 4 | Walls / obstacles between ghosts and targets | reroute ghost paths around walls |
| 5 | Timer pressure: must commit faster | step economy |
| 6 | Multi-segment ghost chains: 3+ commits before time runs out | coordination across many ghosts |
| 7 | Composite: many targets, branching layout, tight timer | full stack |

## Win condition
`mrzduxdbbk()` returns `vgwycxsxjz.safkknjslo` — the world model's "all
targets covered" flag. When True, `self.qgzorkgosv = True`, next step calls
`self.next_level()`.

## Lose condition
`ptayayjhqx()` is True if either:
- the timer sprite scrolled fully off-screen (`abjneovbvx`:
  `-twyixucrqi.x > twyixucrqi.width`), or
- the world model raised its loss flag (`zvuxrhnlcb`).

`hctlyapjnq` set, next step calls `self.lose()`.

## Internal state
- world model `vgwycxsxjz` (`qxlodtievc`) — owns avatar, ghosts, targets,
  per-tick simulation
- step counter `ucorwtereb` — mod-2 used to advance the timer sprite
- timer sprite `twyixucrqi` (tag `evgpfjbmvf.ofihnvwckg`)
- pre-commit / post-commit flags `qgzorkgosv`, `hctlyapjnq`
- inside the world model: ghost path list (sequence of moves per past commit)
  replayed on every step

## Notable code patterns
- Ghost replay: the world model stores per-commit move sequences and replays
  them every step in lock-step with the live avatar. Reusable as "every past
  attempt is also playing right now" mechanic.
- Moving timer sprite that the player races against — slides 1 cell every
  two `step()` calls (`if ucorwtereb % 2 == 0`). Cheap, visual budget.
- Two-flag commit: `qgzorkgosv` (win pending) and `hctlyapjnq` (lose pending)
  set during step but not actioned until the next step — lets animations
  finish first.
- World-model encapsulation: `vgwycxsxjz.step()` advances ghost simulation
  separately from action handling — clean separation between sim and input.
