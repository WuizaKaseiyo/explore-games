# sb26 — mastermind-feedback

## Summary
The board is a guess board: a row of `quhhhthrri` slots is the player's
working sequence; a row of `lngftsryyw` candidate items is the source. The
player clicks a candidate item to "select" it, then clicks a destination
slot to place it; ACTION5 commits the row as a guess, draining 1 energy
(`sjcuorclg`, starting at 64) and producing a per-slot hint (correct in
position / correct only in colour / wrong) painted onto the slot pixels by
`xjxrqgaqw` animation. ACTION7 undoes a placement. The puzzle is to find a
valid sequence before energy runs out — Mastermind / Wordle style.

## Action mapping

| Action | Semantic (game-specific) | Gate / when valid |
|---|---|---|
| ACTION5 | Submit current row; consume 1 energy; play hint animation | always while energy > 0 |
| ACTION6 | Click an item or destination slot to swap / place | always |
| ACTION7 | Undo last placement (history `uvawsoycr`) | history depth ≥ 2 |

(`available_actions=[5, 6, 7]`. Note: no movement keys.)

## Per-level mechanic progression

| Level | Mechanic introduced (or composed) | Specific challenge / constraint |
|---|---|---|
| 1 | Few slots (2-3), small palette, generous energy | tutorial: place + submit |
| 2 | More slots (4); first introduction of colour/position partial-match hints | learn what each hint colour means |
| 3 | Larger palette, longer sequence | combinatorial pressure |
| 4 | "Stack" / framed structure: items arranged in a nested frame `qaagahahj` of multiple (e.g. 3-item, 5-item) sub-sequences | navigate frames with stack history |
| 5 | More frames; locked items move based on submit feedback | feedback animation (`jpgkxnvgqo`) plays on submit |
| 6 | Larger palette and longer guess sequences | deeper search |
| 7 | Composite: nested stack, large frame, partial-match palette | full mastermind challenge |
| 8 | Final composite | nothing new, full stack |

## Win condition
`dbfxrigdqx`: when the last slot is correct (`pmygakdvy == len-1` and `wrudcanmwy=True`),
play winning animation (`lmvwmlqtw`) for 16 ticks then `self.next_level()`.

## Lose condition
Energy `sjcuorclg` reaches zero (or attempting to submit at zero) →
`self.lose()`. Also: hitting an obstacle that drains many energies or three
strikes can end early.

## Internal state
- candidate items list `qaagahahj` (sorted top-down then left-right)
- guess slots list `wcfyiodrx` (target row sprites)
- frame → items map `rzbeqaiky`
- placement stack `buvfjfmpp` (list of (frame, idx) for current path)
- placed-marker list `jyuoktbrc` (visual breadcrumb sprites)
- selected source `lqcskynzr`
- energy `sjcuorclg` (initial 64)
- many animation phase ints (one per phase): `xjxrqgaqw`, `bbiavyren`,
  `lmvwmlqtw`, `japgbruyb`, `ftyhvmeft`, `jlcrtmkes`, `modqnpqfi`, `artsfnufc`
- per-step easing dict `xshdlymmy` (sprite → target colour, blends 1/tick)
- undo history `uvawsoycr` (list of state snapshots)

## Notable code patterns
- Phase-tagged animations via `>=0`/-1 sentinel ints: each animation phase
  has its own counter. Step() is one big "if phaseN >=0" else-chain. Cleanly
  models long animation sequences.
- Per-pixel hint stamping: `bnwkxafnfc.pixels[cuyxtqhdus + 1, 1:-1] =
  rumqsocgtj` — paints a horizontal stripe per-row in the slot's pixel grid
  to show "you got X right". Visible while animation runs.
- Easing colour blend: `xshdlymmy` is a dict where each tick the sprite's
  colour walks one step toward target via `np.sign`. Simple monotonic ease.
- Undo by snapshot: full position + visibility list saved per turn; restore
  on ACTION7.
- Background "freeze" `lvctpsmff`: capture the current rendered scene into a
  64×64 sprite to act as visual hold while sub-state animations play.
