# sk48 — paired-trail-match

## Summary
Each level has multiple "head" sprites (`epdquznwmq`) on a constrained track
of cell sprites (`elmjchdqcn`). Heads come in matched pairs (`xpmcmtbcv`).
WASD moves the active head; whenever it moves, every cell behind the head
gets coloured (visible trail of `qtjqovumxf` segments). The pair-mate also
moves in lock-step (mirrored axis). The win condition: at every position
along the trail, the colour painted by head A matches the colour painted by
head B's mate, cell-by-cell. Click a head (ACTION6) to make it the active
one; ACTION7 undoes one move.

## Action mapping

| Action | Semantic (game-specific) | Gate / when valid |
|---|---|---|
| ACTION1 | Move active head up; extends or shrinks trail | always (move clamped by walls) |
| ACTION2 | Move active head down | as above |
| ACTION3 | Move active head left | as above |
| ACTION4 | Move active head right | as above |
| ACTION6 | Click a head to switch which is active | only on heads (not `wallBase*`) |
| ACTION7 | Undo last position-snapshot | snapshot stack ≥ 2 |

## Per-level mechanic progression

| Level | Mechanic introduced (or composed) | Specific challenge / constraint |
|---|---|---|
| 1 | Single head pair, simple path, no pickups | tutorial: walk both heads to mirror trails |
| 2 | Trail "pickups" (cells with visible paint targets) — colour matters | trails must visit specific cells |
| 3 | Walls (`mkgqjopcjn`) constrain trails | route around obstacles |
| 4 | Multiple head pairs, click to switch active | manage 4+ heads via ACTION6 |
| 5 | Reverse step (back into trail) shrinks tail by one | introduces shrink operation |
| 6 | Branching tracks (perpendicular bridge `irkeobngyh` allows orthogonal jump) | trail can change axis |
| 7 | Tight step budget (196 default), longer paths | step economy |
| 8 | Composite: many heads, branching, walls, mid-trail bridges | full stack |

## Win condition
`gvtmoopqgy()` returns True when, for each pair, every "child indicator"
(`jdojcthkf`) sprite is visible — meaning at every position the trail
colours of both members match. Triggers a 35-frame celebrate animation
(`lgdrixfno`), then `self.next_level()`.

## Lose condition
Step counter `qiercdohl` (init 196) drains; reaches 0 → `self.lose()`.

## Internal state
- active head `vzvypfsnt`
- pairs dict `xpmcmtbcv` (head → mate)
- trails dict `mwfajkguqx` (head → list of trail sprites)
- visited-cells dict `vjfbwggsd` (head → list of paint cells under each
  trail segment)
- match-indicator dict `jdojcthkf` (mate → list of indicator sprites)
- pending-move list `ljprkjlji` for animated tween, removed `hadfnehqh`
- pickup queue `pzzwlsmdt` / target-spawn queue `rztawzist`
- snapshot stack `seghobzez` for ACTION7 undo
- step counter `qiercdohl`, init 196
- celebrate animation tick `lgdrixfno`, ramps `0..35`
- `xsoixcero` flag — head was just clicked (suppresses next move's tail-drag)

## Notable code patterns
- Trail-as-sprite-list: `mwfajkguqx[head]` is a list of segment sprites.
  Each move pre-pends one (extend) or pops the front (shrink). Visual chain
  is just the list rendered.
- Mirrored-axis pair: head's mate is identified by matching pixel `[2,2]`
  colour (`pphvqzjirf == bcwsrdcswp.pixels[2,2]`). When the active head
  moves, the mate moves opposite by axis-flip.
- Per-cell match indicator: `jdojcthkf[mate]` produces an overlay sprite
  per cell that's only visible when colours match — a literal visual diff.
- Snapshot with rotation count: `seghobzez` stores `(sprite, x, y,
  trail_len)` per head, and `(sprite, x, y, 0)` per cell — letting undo
  re-spawn the right number of trail segments via `crbbymputr`.
- Bridge tile: `irkeobngyh` cell allows a head to change axis mid-track.
  Reusable as "perpendicular passage".
