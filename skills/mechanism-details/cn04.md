# cn04 — rotate-translate-jigsaw

## Summary
Each level shows several jigsaw-piece sprites with green-coloured "8"
connectors on their boundaries. The player clicks a piece to select it, moves
it with arrow keys, and rotates it with ACTION5 (90° clockwise). The win
condition is that every "8" connector pixel coincides with another piece's
"8" connector pixel — when matched, both sides flip from "8" to "3"
(visualising the snap). Levels 5+ obscure non-selected pieces by recolouring
them flat colour 4 (so the player must remember piece shapes). Step budget
150.

## Action mapping

| Action | Semantic (game-specific) | Gate / when valid |
|---|---|---|
| ACTION1 | Move selected piece up by 1 | a piece is selected |
| ACTION2 | Move selected piece down by 1 | a piece is selected |
| ACTION3 | Move selected piece left by 1 | a piece is selected |
| ACTION4 | Move selected piece right by 1 | a piece is selected |
| ACTION5 | Rotate selected piece 90° clockwise | a piece is selected |
| ACTION6 | Click a piece to select / deselect | always |

## Per-level mechanic progression

| Level | Mechanic introduced (or composed) | Specific challenge / constraint |
|---|---|---|
| 1 | Two pieces, axis-aligned connectors | learn click-to-select + arrow nudges |
| 2 | Three pieces; one connector pair only | force selecting the right piece first |
| 3 | Rotation required: at least one piece must be rotated 90° | introduces ACTION5 |
| 4 | Cluster of 4+ pieces, all rotations needed | composition of move + rotate |
| 5 | Non-selected pieces flat-coloured (`mctam=True` when level_index ≥ 4) | working memory: shape vanishes after deselect |

(`levels` array has 5 entries; the game has no extra tutorial level.)

## Win condition
After every action, `gjhtwbvrel` recomputes which "8" pixels coincide between
two distinct sprites and snaps them to "3". Then `exlcvhdjsf` verifies no
remaining "8" pixels exist anywhere — if so, `self.next_level()`.

## Lose condition
`_action_count >= self.guweh (150)` → `self.lose()`. No hazard, no collision
fail.

## Internal state
- selected sprite (obfuscated `weqid`)
- `agupi` — backup of original pixels per sprite (for restoring on deselect)
- `npwwu` — pristine pixel cache per sprite
- `dpmge` — set of (x,y) offsets per sprite that have already snapped
- `mctam` flag — if level_index ≥ 4, dim non-selected sprites
- `fubdf` flag — track click-just-happened so next valid actions can change
- `_step_counter_ui` (`qdcvayjdkm`)

## Notable code patterns
- Pixel-level connector matching: render world to absolute coords, group "8"
  pixels by world (x, y), pairs of size 2 are matched. Could be reused for any
  "snapping" mechanic with arbitrary pixel patterns.
- Rotation-aware snap registry: `dpmge` stores connector offsets in the
  sprite's local 0-rotation frame, then rotated for display. Avoids
  desynchronising when the player rotates a piece after partial snap.
- Selected-piece highlight: replace "8" with "0" while selected, restore on
  deselect; selected sprite gets `set_layer(4)` for z-order.
- Memory-pressure variant: `mctam` flat-colours non-selected pieces so each
  click reveals a piece momentarily — easy lever for difficulty.
