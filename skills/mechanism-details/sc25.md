# sc25 — spell-grid-pattern

## Summary
The player roams a top-half map with a movable wizard avatar (`nwxssyzit`)
using WASD. The bottom-right corner shows a 3×3 "spell-slot" grid; clicking
a slot (ACTION6 in that region) toggles it on/off. When the toggled pattern
matches one of the known spell-legends — fireball (`fpokrvgln`), teleport
(`jzukcpajs`), resize (`aprnrzeyj`) — that spell auto-casts. Spells modify
the world: teleport jumps the wizard to a target marker, fireball destroys
fire-cleared cells along a line, resize changes the wizard's pixel size to
fit through small doors. Each level grants only certain spells via
`wdsxxkugj` data. Step budget per level via `sykpecmoq`.

## Action mapping

| Action | Semantic (game-specific) | Gate / when valid |
|---|---|---|
| ACTION1 | Move wizard up | not in cast / exit animation |
| ACTION2 | Move wizard down | as above |
| ACTION3 | Move wizard left | as above |
| ACTION4 | Move wizard right | as above |
| ACTION6 | Click — toggles a spell-slot if click is in 3×3 grid region; else may interact (e.g. door) | always |

## Per-level mechanic progression

| Level | Mechanic introduced (or composed) | Specific challenge / constraint |
|---|---|---|
| 1 | Tutorial: movement only; teleport spell unlocked, hint highlighted (`highlighted_spell`) | learn ACTION6 toggles + spell auto-cast |
| 2 | Add fireball; obstacle (`bbyayvbjq` brick) blocks WASD path until fired | sequence: cast fireball at right cell |
| 3 | Add resize; door requires "small" wizard | composition of fireball + resize + walk |
| 4 | Multi-step: teleport across blocked region, then fireball, then walk | three-spell composition |
| 5 | Energy / step budget tightened | minimise wasted casts |
| 6 | Composite: multiple teleport markers (cycle which target via `current_teleport_index`), multi-segment doors | full stack |

## Win condition
Wizard enters the exit cell `cflwkfoggh` overlapping a door — `qddsvybuqj`
animates entry, then `self.next_level()`. Two-door chains use `second_doors`.

## Lose condition
`hgthkqvmfa` ticks `actions_taken`; if greater than `sykpecmoq` (per-level
budget), `self.lose()`.

## Internal state
- wizard sprite `cflwkfoggh`
- 3×3 boolean toggle grid `spell_slot_active`
- 3×3 of clickable spell-slot sprites `clickable_spell_slots`
- `wdsxxkugj` — list of allowed spells for this level (loaded from `wdsxxkugj`
  level data)
- step budget `sykpecmoq`, current count `actions_taken`
- per-spell animation dicts (`teleport_animation`, `fireball_animation`,
  `size_change_animation`, `auto_cast_animation`,
  `spell_pattern_demo_animation`, `spell_slots_flash_animation`,
  `exit_animation`) — each tracks `frame`, `max_frames`, related sprites
- spell legends dict `spell_legends` (per-name 3×3 boolean pattern)
- `highlighted_spell` for level-1 hint demo
- target lists: `teleport_targets`, `small_teleport_targets`, `doors`,
  `second_doors`, `energy_packs`, `active_teleport_indicators`

## Notable code patterns
- Spell as static 3×3 boolean grid: `spell_legends = {"jzukcpajs": [[T,T,F],
  [F,T,F],[F,F,F]], ...}`. To detect, compare current toggle grid against
  each. Reusable for "shape-recognition trigger".
- Per-spell animation dict with `active`/`frame`/`max_frames` — each spell
  is its own little state machine in the same step() loop.
- Action_ui sprite is a row inside the player avatar: pixels are filled
  proportional to `actions_taken / sykpecmoq` — depleting bar drawn into a
  sprite, not via HUD.
- Spell allow-list via level data `wdsxxkugj` — not all spells available on
  every level; cast attempts to disallowed spells fail silently.
- Fireball "fire path" sprites spawned and removed over `max_frames=6` —
  showing the laser line as an animated trail.
