# lf52 — fog-of-war-sokoban

## Summary
The player moves a single avatar with WASD around a Sokoban-like grid pushing
exactly one block onto exactly one target tile. The twist is fog-of-war:
every move increments a step-cost counter (`asqvqzpfdi`), and the player can
click a corner indicator (ACTION6 in the bottom-left 16×16 region) to briefly
reveal the level — at the cost of a "burn" animation that wastes 20 extra
steps. Higher levels have larger budgets but proportionally bigger maps.
ACTION7 undoes the last commit (frame queue replay).

## Action mapping

| Action | Semantic (game-specific) | Gate / when valid |
|---|---|---|
| ACTION1 | Move avatar up; push-block if a block is in front | always |
| ACTION2 | Move avatar down | always |
| ACTION3 | Move avatar left | always |
| ACTION4 | Move avatar right | always |
| ACTION6 | Click bottom-left corner (x<16, y>48) → reveal-flash; +20 step penalty | only if reveal still available (`zvcnglshzcx`) |
| ACTION7 | Undo last move (replay snapshot frames) | snapshots present |

## Per-level mechanic progression

| Level | Mechanic introduced (or composed) | Specific challenge / constraint |
|---|---|---|
| 1 | Tiny visible map, 1 block, 1 target; budget tight (64) | tutorial: push block on target |
| 2 | Full fog-of-war introduced; only avatar's 3×3 neighbourhood visible | reveal click `zvcnglshzcx` becomes useful |
| 3 | Larger room, 1 block, walls around | navigate fog without bumping walls |
| 4 | Block placed on a path that requires backtrack | undo `ACTION7` matters |
| 5 | Multiple "false" blocks (decoys); only one is the true block | identify correct block under fog |
| 6 | Larger budget (`whtqurkphir>=6` → 64*10) but more obstacles | scale up |
| 7 | Hazard tiles (movement onto them counts as immediate loss) | watch where you step |
| 8 | Branching paths with dead-ends | explorers must reveal smartly |
| 9 | Multi-block? (still single push but multiple decoys + corridors) | full layout |
| 10 | Final composite | nothing new, full stack |

## Win condition
`ikhhdzfmarl.iajuzrgttrv` (world model "all targets covered") flips True
after the push. Step queue drains, then `self.next_level()`.

## Lose condition
- `ikhhdzfmarl.evxflhofing` — pushed into a non-pushable / out-of-bounds
- step budget thresholds based on `whtqurkphir` (level number):
  - level 1: `asqvqzpfdi >= 64`
  - levels 2-5: `asqvqzpfdi >= 64*5`
  - levels 6+: `asqvqzpfdi >= 64*10`

## Notable code patterns
- Fog reveal as 10-step animation: builds 20 frames (10 forward + 10 reverse)
  by stamping a different mask region per frame. Reusable as "scan beam" UI.
- Step-cap by level via match-on-`whtqurkphir` — clean way to scale budget.
- Per-action match statement (`match dmzyzawoubn:`) is a cleaner pattern than
  if/elif for fixed action ids.
- World model has `iajuzrgttrv`/`evxflhofing` boolean flags exposed
  externally — game class doesn't compute predicates, world model raises
  "win pending"/"lose pending" each tick.
- Reveal action has a special bottom-left coordinate gate
  (`x<16 and y>64-16`) — distinct from board clicks.
