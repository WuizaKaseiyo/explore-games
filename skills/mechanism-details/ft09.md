# ft09 — stamp-color-cycle

## Summary
The board is a 16×16 grid of cells with a few "constraint" sprites (3×3 plus a
border) and many "tile" sprites (`Hkx` or `NTi`). Clicking a tile cycles its
centre colour through a small palette (`gqb`, default `[9, 8]`); the player
also has a 3×3 stamp pattern (`irw`) that decides which neighbours to cycle
together. Constraint sprites encode an 8-direction rule: if the constraint's
boundary cell is "0", the neighbour tile's centre colour must equal the
constraint's centre; if any non-zero, must differ. The puzzle is to find a
clicking sequence that satisfies every constraint cell of every constraint
sprite.

## Action mapping

| Action | Semantic (game-specific) | Gate / when valid |
|---|---|---|
| ACTION6 | Click a tile or stamp template (`Hkx`, `NTi`, `gOi`) | only on a clickable tile |

(`available_actions=[6]` — pure click game.)

## Per-level mechanic progression

| Level | Mechanic introduced (or composed) | Specific challenge / constraint |
|---|---|---|
| 1 | Single constraint, default stamp (centre-only); 2-colour palette | tutorial: click each tile to set colour |
| 2 | First non-trivial stamp pattern: full 3×3 (`elp` level data) | one click cycles 9 cells at once |
| 3 | Multi-constraint board; tiles between two constraints | ordering matters; one cycle can break another rule |
| 4 | Stamp-template tile (tag `NTi`) — clicking a template overrides current stamp from its own pixels | switch stamps mid-puzzle |
| 5 | 3-colour palette (`cwU` overrides `gqb`) | longer cycle, more choices |
| 6 | Composite: many constraints, multiple template tiles, full 3-colour 3×3 stamps | full stack |

## Win condition
`cgj()`: for every constraint sprite, for each of its 8 boundary cells, look
at the neighbour tile (offsets ±4) and check the equal/unequal predicate
(boundary "0" → equal; otherwise ≠). All must hold → `self.next_level()`.

## Lose condition
`lpw.lph()` (step counter `kCv`) returns False when budget exhausted →
`self.lose()`. There is also a special level-1 visualisation: invalid clicks
flash a tutorial sprite for 4 ticks (`our` countdown).

## Internal state
- step counter `lpw` (`sve`)
- current stamp `irw` (3×3 boolean grid)
- palette `gqb` (list of palette colour ids)
- constraint sprites list `gig` (tag `bsT`)
- tile sprites lists `fhc` (tag `Hkx`), `mou` (tag `NTi` — also stamp templates)
- click-target sprite `blr` set on each click
- `zth` — tutorial helper sprite for level 0
- `our` — ticks remaining for tutorial flash

## Notable code patterns
- Stamp-as-mask: the 3×3 `irw` is interpreted as "for each cell where 1,
  cycle the neighbour at that relative offset". Trivially extensible to
  arbitrary stamp shapes.
- Palette cycle: `kNa = (kNa+1) % len(self.gqb)` — simple cyclic increment.
- Constraint as 3×3 sprite: middle cell is the "centre colour", outer 8 cells
  encode `0`=equal/non-zero=different rules. Clean way to embed logic in a
  visual sprite.
- Click-template-tile to change stamp: `NTi` tile's pixels are themselves the
  next stamp pattern (`eHl[j][i] = 1 if pixels==6`), enabling "tools you pick
  up" without state.
- 16×16 camera with 4×4 cell scaling — `Camera(0,0,16,16,4,4,...)`. Reusable
  for any tilemap micro-game.
