# bp35 — gravity-fall-navigation

## Summary
The player auto-falls one row per step under gravity. Side-step actions let
the player change column on the way down to land on platforms, miss spikes,
and reach the level's gem (goal). Some tiles flip the gravity direction (so
the player suddenly "falls" up, left, or right), turning the puzzle into a
multi-axis platformer routing problem. A dedicated rendering pipeline
(`tehvqeiqsdu`) plays back animated frames of the fall, and the puzzle loop
alternates between collecting input and showing the queued animation.

## Action mapping

| Action | Semantic (game-specific) | Gate / when valid |
|---|---|---|
| ACTION3 | Side-step left while falling | always |
| ACTION4 | Side-step right while falling | always |
| ACTION6 | Click a clickable side-panel target (e.g. portal/teleporter) | only if a clickable sprite exists on screen |
| ACTION7 | Undo last commit (replays prior frame queue) | undo available |

(ACTION1/ACTION2/ACTION5 are wired in `urzvqcxbsz` for symmetry, but
`available_actions=[3,4,6,7]` exposes only side-step + click + undo.)

## Per-level mechanic progression

| Level | Mechanic introduced (or composed) | Specific challenge / constraint |
|---|---|---|
| 1 | Single gravity axis (down); land on the lone platform with the gem | tutorial: only side-step is needed |
| 2 | Spikes that lose if hit; first platform-shape lattice | route through gaps without touching spike tag |
| 3 | First gravity-flipper tile: lands on a "flip" pad and direction inverts | mid-fall axis change introduced |
| 4 | Two-axis solution: must flip horizontally then vertically before reaching gem | composition of two flips |
| 5 | Moving / wrap-around obstacles; portal sprites accessible via ACTION6 | click teleports player to paired portal |
| 6 | Step-cap pressure: `asqvqzpfdi >= 64*5` triggers loss | budget gameplay |
| 7 | Larger grid `whtqurkphir >= 6` allows budget `64*10` but more flips | extended budget but more chained mechanics |
| 8 | Multiple gem collectibles required before exit | collect-all variant |
| 9 | Final composite: portals + flips + spikes + multi-gem | nothing new, full stack |

(`whtqurkphir` is the level number cached in the level model; `qjwmwkhrml`
loads the level layout, `jpexoivelf` initialises sprite physics.)

## Win condition
`self.oztjzzyqoek.nkuphphdgrp` flag set when the player sprite occupies the
gem cell after the falling animation finishes. Triggers `self.next_level()`
once the deferred frame queue drains.

## Lose condition
Three predicates in `step`:
- `oztjzzyqoek.jrhqdvdwpsb` — touched a spike.
- `whtqurkphir == 1 and asqvqzpfdi >= 64` — level 1 step budget.
- `whtqurkphir >= 6 and asqvqzpfdi >= 64*10` — late-level budget.
- `whtqurkphir < 6 and asqvqzpfdi >= 64*5` — mid-level budget.
All call `self.lose()`.

## Internal state
- world model (obfuscated `oztjzzyqoek`) — owns all level sprites and gravity
- frame renderer (`tehvqeiqsdu`) holds `frames_to_render` queue
- `krqzxbshzqn` flag — pending render needed
- `heywwwvrogx` flag — animation currently playing
- `hbqwwgceeqp` action counter
- `available_actions=[3,4,6,7]` (note: 1, 2, 5 reserved but disabled)

## Notable code patterns
- Frame-queue rendering: every action enqueues a list of frames, base step()
  drains one per call. Lets a 1-frame-per-tick "falling" animation be modelled
  as a normal turn-based game.
- Click discovery in `_get_valid_actions`: gathers all sprites whose name
  contains `qclfkhjnaac` / `yuuqpmlxorv` / `oonshderxef` / `lrpkmzabbfa`
  (different portal kinds), then converts grid coords to display coords.
- Per-level budget gating by `whtqurkphir` — nested branches for budget per
  level. Reusable HUD pattern: budget scales with level number.
- `set_blocking(BlockingMode.BOUNDING_BOX)` on platforms for fast collision.
