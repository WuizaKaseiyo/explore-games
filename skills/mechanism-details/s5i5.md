# s5i5 — rotate-resize-stick

## Summary
Each level has several "stick" sprites (`agujdcrunq`) with one half being a
solid colour and the other half being an end-cap. Sticks are tagged with a
hue. Clicking a colour swatch (`myzmclysbl`) rotates every stick of that hue
90° around its anchor end. Clicking a stick on its long axis at one half
extends/shrinks the stick by one unit (`bjntvocxdv`) in that direction.
Children sticks (registered in `enplxxgoja`) follow their parent's rotations
and translations. Goal: place "marker" cells (`cpdhnkdobh`) onto target
cells (`zylvdxoiuq`) by manipulating sticks; if sticks overlap each other,
the move is reverted.

## Action mapping

| Action | Semantic (game-specific) | Gate / when valid |
|---|---|---|
| ACTION6 | Click a stick (cycles its length up/down depending on which half is clicked) OR click a colour swatch (rotates all sticks of that colour) | always |

(`available_actions=[6]` — pure click.)

## Per-level mechanic progression

| Level | Mechanic introduced (or composed) | Specific challenge / constraint |
|---|---|---|
| 1 | Single stick, single target | tutorial: click stick to extend, watch end reach target |
| 2 | Colour swatch click — rotates the stick 90° | introduce ACTION6-on-swatch path |
| 3 | Two sticks of different colours | each colour rotates independently |
| 4 | Children sticks (parent stick rotates → child rotates around same pivot) | hierarchy with `Children` level data |
| 5 | Multiple targets requiring multiple sticks to land their tips | parallel target solve |
| 6 | Overlap rejection: if any rotation/extend causes two sticks to collide, rollback | learn what's not allowed |
| 7 | Tighter step budget; more sticks | optimise sequence |
| 8 | Composite: multi-colour, hierarchical sticks, overlap-tight layout | full stack |

## Win condition
`vodebmynqs()`: every `cpdhnkdobh` marker has a `zylvdxoiuq` target at the
exact same (x,y). All match → `self.next_level()`.

## Lose condition
Step counter `okmxyzxpez` (`ivslbwhvug`) drains; zero → `self.lose()`.

## Internal state
- step counter `okmxyzxpez`
- swatch → list-of-sticks dict `dfyrdkjdcj` (`gdgcpukdrl` swatch → matching
  `agujdcrunq` sticks)
- parent → children dict `enplxxgoja` (loaded from `Children` level data)
- snapshot dict `acgkuydgqx` (sprite → cloned-original) for rollback after
  bad moves
- `ssemyeftxy`, `hfcjuvfshg` — currently selected swatch and previous click
  state

## Notable code patterns
- Snapshot-and-rollback: every action saves clones via `yxdtnnaclf`, applies
  the move, calls `ulzimrggno()` to detect overlap; if collision, restore
  from clones, otherwise discard snapshots. Reusable as "speculative
  execution with conflict rollback".
- Stick orientation deduced from end-cap pixel: `fhkoulsvoi` reads the cap
  pixel position to return 0/90/180/270.
- Length manipulation `ldmrjbrvwa(ufhuxyighd, index)`: rebuilds the pixel
  array in-place by `np.full((nxzmhkgggg, bjntvocxdv), cxjpqzcsao)`,
  preserving the cap and shifting the anchor as the length changes.
- Hierarchical translation: `qdfmefxmo` translates a parent and then
  recursively all of its children.
- Click two-mode: same ACTION6 click can be a swatch click (rotation) or a
  stick click (resize) — branch on which sprite was hit.
