# ka59 — direction-tilt-detonation

## Summary
The grid contains an active block (selected via ACTION6 click) plus walls,
target (`rktpmjcpkt`) markers, "trigger" blocks (`gobzaprasa`) that detonate
when slid against, and enemies (`Enemy`) that chase the player. Pressing a
direction (ACTION1-4) slides the active block one cell that way; if the
trigger condition is met (`egsdqzlidg` — block fully scanned), it explodes
and pushes neighbouring blocks one cell in the orthogonal direction by
spawning ricochet sprites (`explode-W-i`). The objective is to land every
target marker on its goal location while not letting an enemy catch the
player.

## Action mapping

| Action | Semantic (game-specific) | Gate / when valid |
|---|---|---|
| ACTION1 | Slide active block up; fires push-collider on top edge | not in detonation phase |
| ACTION2 | Slide active block down; push-collider on bottom edge | not in detonation phase |
| ACTION3 | Slide active block left; push-collider on left edge | not in detonation phase |
| ACTION4 | Slide active block right; push-collider on right edge | not in detonation phase |
| ACTION6 | Click a clickable block (tag `xlfuqjygey`) to make it active | always |

## Per-level mechanic progression

| Level | Mechanic introduced (or composed) | Specific challenge / constraint |
|---|---|---|
| 1 | Single block, single target | tutorial: slide block onto target |
| 2 | Wall sprites (tag `divgcilurm`) block movement | learn collision mechanic |
| 3 | First trigger block; pressing it detonates ricochets | introduces explosion mechanic |
| 4 | Multiple movable blocks; ACTION6 picks which one is active | block selection important |
| 5 | Enemies (`umbwvqfttt`) appear and chase player every detonation phase | timing-based pressure |
| 6 | Multi-trigger chains: one detonation triggers another | recursive cascade through `tesoceiypr` |
| 7 | Composite final: walls + multi-targets + chase enemies + chains | full stack |

## Win condition
`cbdaoltbck()`: every `rktpmjcpkt` (marker) overlaps an `xlfuqjygey` block,
AND every `ucjzrlvfkb` cursor overlaps the `nnckfubbhi` goal. Both
conditions → `self.next_level()`.

## Lose condition
- Enemy reaches player position in `tmuauqrmwt` (greedy chase up to 6 steps).
- Step counter `rciyayewnv` reaches zero.
Both call `self.lose()`.

## Notable code patterns
- Edge-strip colliders: build 4 separate Sprites that wrap the block's bounds
  by 1 cell and only have non-(-1) on one edge. Each ACTION direction adds
  one edge strip to the level so collision tests detect what's adjacent that
  way. Reusable for any "what's bordering me on side X" check.
- Cascading detonation via `tesoceiypr` — recursively applies displacement
  vectors to every neighbour the explosion could push.
- Per-block pending move dict `zhcrzgpwcp` (sprite → (dx, dy)) — implements
  "many things move together" without collision interleaving.
- Greedy enemy AI `tmuauqrmwt`: step `erbgkfplcm` cells towards player along
  the dominant axis; if reaches player, lose. Simple chase template.
- Animation frames build from `sprites[f"explode-{width}-{i}"]` — pre-baked
  pixel art keyed by size and animation frame index.
