# tu93 — lockstep-multi-maze

## Summary
A single direction press moves every walkable agent (`albwnmiahg`) one cell
that way. Movement is valid only if every agent's destination is on the
walkable underlay (`vhlesexlqd` tile array, value 2). Each agent rotates to
face its move direction; secondary agents (`vllvfeggte`, `zzuxulcort`,
`natiyqayts` — different walking species with bouncing / chasing / blocking
behaviour) move per tick under their own rules and may interact with the
primary agents. Bringing every primary agent onto its exit (`xboyuzuyxv`)
wins; running out of steps loses; running out of agents loses.

## Action mapping

| Action | Semantic (game-specific) | Gate / when valid |
|---|---|---|
| ACTION1 | All primary agents face up and move 1 cell up (lockstep) | only if every agent's destination is walkable (= 2 in underlay) |
| ACTION2 | All face down + move | as above |
| ACTION3 | All face left + move | as above |
| ACTION4 | All face right + move | as above |

(`available_actions=[1, 2, 3, 4]`. After a move the world enters two
sub-phases: phase 1 advances secondaries; phase 2 evaluates win/lose.)

## Per-level mechanic progression

| Level | Mechanic introduced (or composed) | Specific challenge / constraint |
|---|---|---|
| 1 | Single agent, simple maze | tutorial: walk to exit |
| 2 | Two agents in separate corridors moving in lockstep | wall blocks one direction → entire move blocked |
| 3 | Three agents | all destinations must clear |
| 4 | Add `zzuxulcort` (bouncing entity that follows you) | dodging mid-tick |
| 5 | Add `natiyqayts` (per-tick rotating obstacle, copies your last rotation) | rotation matters |
| 6 | Add `vllvfeggte` (decorative pickup that despawns on collision but blocks paths) | collect-or-avoid logic |
| 7 | All agent species + walls | combination |
| 8 | Multiple species & multiple agents | full stack |
| 9 | Composite final: max agents, max enemies, tight budget | nothing new, full stack |

## Win condition
`rodqliwlhy()` (post-secondary-tick): every `albwnmiahg` agent occupies an
`xboyuzuyxv` exit. → `self.next_level()`.

## Lose condition
- step counter `tsoqrmroqn` (`klmvbszflr`) reaches 0
- no `albwnmiahg` agents remain (all destroyed by enemies / pickups)
Both call `self.lose()`.

## Internal state
- step counter `tsoqrmroqn`
- step phase `iuubfszcoi` (0 = await input, 1 = primary move done — tick
  secondaries, 2 = check secondary collisions and finalise)
- per-secondary rotation history `sdiguidlbg` (sprite → list of past rotations)
- walkable underlay tag `vhlesexlqd` — pixel value 2 = walkable
- "marked" pixel `[0, 1] == fltjxhzdlv` — agent has been "tagged" by some
  enemy interaction; tracks transient state inside the sprite

## Notable code patterns
- Three-phase step machine (`iuubfszcoi` 0/1/2): primary move → enemy ticks
  → win/lose evaluation. Reusable for "all agents move, then world ticks".
- Walkable underlay as a single sprite (tag `vhlesexlqd`) with pixel value 2
  marking walkable cells. Constant-time `pixels[i, j] == 2` test.
- Rotation-history queue per secondary: enemies copy the player's previous
  rotations. Reusable as "shadow-of-past-action" enemy.
- Tag-driven species: `vllvfeggte` (collectible/blocker), `zzuxulcort`
  (bouncer), `natiyqayts` (rotator). Each has its own tick function
  (`yacjieihbk`, `irydcdcqyd`, `jjqtojitqv`).
- Win check `vpaafwwtxk` then `kqpvpzoaim`/`yacjieihbk`/`jjqtojitqv` — all
  enemy ticks happen before final win/lose.
