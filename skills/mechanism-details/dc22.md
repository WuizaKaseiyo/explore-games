# dc22 — remote-arm-pickplace

## Summary
The player walks an avatar (`nxhz`) around a maze of paths, walls, doors, and
pressure plates. Some squares carry pickup objects (`bynyvtuepbt-object`)
that, when collided with, attach to the avatar; clicking a pressure plate
arrangement causes a separate "remote arm" to drive paired sprites (e.g. a
key-and-lock pair). Pressing a button or stepping on a pressure plate of
colour X makes every sprite tagged with X become tangible (puzzle gates open
based on plate state). Walls block movement; certain levels add a teleport-arm
that animates a sprite into target slots through path-following.

## Action mapping

| Action | Semantic (game-specific) | Gate / when valid |
|---|---|---|
| ACTION1 | Move avatar up | not mid-arm-animation, not on a wall above |
| ACTION2 | Move avatar down | as above |
| ACTION3 | Move avatar left | as above |
| ACTION4 | Move avatar right | as above |
| ACTION6 | Click on a sprite to drive the remote arm / interact | always |

## Per-level mechanic progression

| Level | Mechanic introduced (or composed) | Specific challenge / constraint |
|---|---|---|
| 1 | Plain maze, single goal pad | tutorial: walk the avatar to the goal |
| 2 | Doors of two colours; pressure plates `pressure-plate` of matching colour | step on plate → matching tag becomes tangible |
| 3 | Pickup sprite (`bynyvtuepbt-object`); avatar carries it | object follows avatar with cached offset |
| 4 | Wider grid + multiple plate colours | colour group state managed via `vfuxmgtevge` dict |
| 5 | Pickplace target squares (drop pickup on a goal cell) | object placement releases avatar |
| 6 | Special level (`level_index == 5` patches a specific tile to add tag `vgiqmhpyxb`) — composite final puzzle | route + key + plate + drop |

## Win condition
Game advances `next_level()` on level-specific predicates (varies per level
helper, e.g. avatar reaches goal pad / all pickups dropped on plates / target
arm slots filled). Pressure-plate state visible via `mbszrqqnqm`. After level
6 completion the engine triggers `self.win()`.

## Lose condition
Step counter HUD `step_counter_ui` (`khximaydsc`) drains; when zero
`self.lose()`. No collision-instant-fail.

## Internal state
- avatar `nxhz` and starting offset `nxhz_start`
- attached pickup `euqqhkqayni` plus `nxhz_attached_kind` ("none"/"hhxv")
  describing what's currently carried
- pressure-plate registry `wzazcqnyxfa` and tag-to-list map `vfuxmgtevge`
- per-step animation flags `jnmawhhrfhh`, `dimvmykkjbg`, `cgqgayyktrv`,
  `cayrfzcwfap` (interp source)
- duplicate-name list `qmxenejanqe` — each `wbze` sprite name has 1..N
  variants; the active variant stays TANGIBLE, others REMOVED, ready to swap
  when state changes (key replaces lock, etc.)

## Notable code patterns
- Sprite-multi-state via name suffix digits: `prefix1`, `prefix2`, ... swap
  visibility/interaction. One slot is tangible at a time; others are REMOVED
  in same position. Reusable for "machine that morphs in place" mechanic.
- Path-cell collision `jrpmxofbar(x, y)`: queries any sprite with tag "path"
  whose render shows non-(-1) at (x,y). Lets paths be rendered as sprites,
  not a tilemap.
- Pressure-plate group activation: tags act as logical channels — every
  sprite with the same single-letter tag belongs to a group; each plate
  picks its group from `wisycusrnd` (looks at the 1-char tag).
- `tzwaxkrztd` does pixel-level overlap (np boolean & np boolean) — better
  than bbox overlap for irregular shapes.
- Bezier-style arm interp for moving objects: `dldhnotovw` re-finds the
  attached hhxv sprite by cached `(prefix, x, y)` after structure rebuilds.
