# cd82 — stencil-paint-sweep

## Summary
The player navigates an 8-position ring of "active basket" slots with
ACTION1-4 (each press snaps to the next ring slot in that direction). Clicking
a coloured paint can (`pqkenviek*`) loads its colour, and clicking a tool
arrow on the canvas commits a sweep that animates the basket out and back,
stamping a region of pixels the active colour matching that slot's
horizontal/diagonal axis. The goal is to make a target canvas (`xytrjjbyib`)
match an example canvas (`eoqnvkspoa-*`) ignoring the diagonal "X" pixels.
Step budget 100.

## Action mapping

| Action | Semantic (game-specific) | Gate / when valid |
|---|---|---|
| ACTION1 | Move basket one slot up | not in animation, < 6 moves before forced commit |
| ACTION2 | Move basket one slot down | as above |
| ACTION3 | Move basket one slot left | as above |
| ACTION4 | Move basket one slot right | as above |
| ACTION5 | Commit the sweep; play stamp animation | a paint can has been clicked |
| ACTION6 | Click paint can / direction arrow / tool sprite | always |

(After 6 movement actions or after a paint-can click, valid action set is
restricted; `_get_valid_actions` filters accordingly.)

## Per-level mechanic progression

| Level | Mechanic introduced (or composed) | Specific challenge / constraint |
|---|---|---|
| 1 | Horizontal sweep only (4 cardinal slots); single colour | tutorial: hit the matching half |
| 2 | Diagonal sweep introduced (4 corner slots) | basket can also fill triangle halves |
| 3 | Multiple colours via several paint cans `pqkenviek-*` | must remember which colour matches which sweep |
| 4 | Background colour custom via `BackgroundColour` level data | learn to ignore non-colour cells |
| 5 | Step-budget pressure: ~15 commits possible | minimise wasted clicks |
| 6 | Composite: full 8 slots, all colours, target equals example except X-diagonals | mask `poqpfcjieu` excludes the two diagonals during compare |

## Win condition
`wvrremwltt`: after every sweep finishes, compare the live canvas pixels to
the example pixels using a mask that excludes both diagonals. If equal,
`self.next_level()`.

## Lose condition
`_action_count >= iewrsdwok (100)` → `self.lose()`. No collision-based fail.

## Internal state
- ring index `xwmfgtlso` (0-7, slot in 8-position basket ring)
- selected colour `knqmgavuh` (set by clicking paint can)
- `aalpkuosy` / `yfobpcuef` / `edjesyzxk` flags for animation phases
- `bjgtofqhv` (active basket sprite) and `iswxsbrge` (sweep direction)
- step counter UI `qzgkhffci` (`aunldyudeb`)
- `nicoqsvlg` table — 8 hard-coded slot configs `(kind, x, y, rotation, dx, dy)`
- `nfhykrqjp` map — slot index → (row, col) on a 3×3 ring layout

## Notable code patterns
- Animation phase machine: 3 distinct phases (`yfobpcuef` = pre-sweep,
  `edjesyzxk` = stamp animation, normal = idle) — branches in `step()`.
- Sweep stamping `rtjwayrycq`: writes a triangular or rectangular slab of
  colour into the live canvas pixel array. Uses np slicing with rotation
  branches.
- Diagonal mask `poqpfcjieu`: explicit boolean grid where the two main
  diagonals are False; reusable as "compare-excluding-X" pattern.
- Action-count gating in `_get_valid_actions`: after 3 moves enables clicks,
  after 6 forces a commit. Good template for "phase-locked" UIs.
