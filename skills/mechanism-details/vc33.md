# vc33 — row-column-swap-stripe

## Summary
The board is a striped layout of stones (`UXg`) flanked by rails (`rDn`)
above and below (or left and right, depending on the tilt direction stored
in `oro` level data). Clicking a marked tile (`ZGd`) flanked by two matching
neighbours swaps stones within its row or column according to a rule
(`ccl` → `gel(ksm, vus)`): the matched neighbour groups exchange pieces
across the marker, producing a target stripe pattern. The win predicate is
that every checkable stone (`HQB`) ends up over a slot of its required
colour (`fZK`). Clicking buttons (`zHk`) auto-paints them based on whether
they're "valid" given the current state.

## Per-level mechanic progression

| Level | Mechanic introduced (or composed) | Specific challenge / constraint |
|---|---|---|
| 1 | Horizontal tilt (`oro=(±1, 0)`); single marker | tutorial: click marker → adjacent groups swap |
| 2 | Vertical tilt (`oro=(0, ±1)`) | swap operates on columns instead |
| 3 | Multiple markers; one swap can break a previous match | ordering matters |
| 4 | Multiple `fZK` slots required to all be filled by matching `HQB` stones | parallel goals |
| 5 | Buttons (`zHk`) appear — auto-paint blue/red based on `krt` validity | learn validity feedback |
| 6 | Larger grid, more rails, intermediate `WuO` blockers | navigation around blockers |
| 7 | Composite final: all rules, both tilts, multiple markers/buttons | full stack |

## Win condition
`gug()`: for every `HQB` stone, find rails (`rDn`) below it then identify the
slot below those rails (`fZK`); confirm at least one slot matches the stone's
end-pixel colour and is at the same axis. All True → handled in animation
helper `vai`, which on next step calls `self.next_level()`.

## Lose condition
Step counter `vrr` (`ehv`, set from `RoA` level data) drains; reaches 0 →
`self.lose()`.

## Internal state
- step counter `vrr` (`ehv`)
- tilt vector `oro: tuple[int, int]` (axis-direction of stripe)
- marker → swap-target dict `dzy` (precomputed in `on_set_level`)
- pending animation `vai: ysn | None` (multi-step interpolation, `None` when
  idle)
- rails `rDn`, slots `fZK`, stones `HQB`, buttons `zHk`, blockers `WuO`,
  swap-source markers `ZGd`

## Notable code patterns
- Axis-abstracted accessors: `urh`, `ebl`, `brj`, `jqo`, `lho`, `utq` —
  every coordinate query is routed through helpers that branch on `oro` so
  the same algorithm works for vertical or horizontal tilt.
- Swap precomputation: `on_set_level` walks every marker and chooses two
  rail neighbours (`osk`, `daL`) whose distance from the marker equals
  twice the marker height, then stores the pair in `dzy`. Lets click
  handler be O(1).
- Validity feedback button: clicking a `zHk` button calls `pso(button)`
  which calls `krt(button)` (validity predicate) — paints blue if valid
  (12), red if not (1). Reusable as "self-testing button".
- Animation as a "next-step iterator" in `vai`: `vai.next()` returns False
  while still animating, True on completion. Cleaner than tick counters.
- Strip slicing for swap: `pmj.pixels = pmj.pixels[:-abs(rsi)]` and
  `chd.pixels = np.vstack([chd.pixels, YVU])` — physically grow one stripe
  while shrinking the other.
